The lead session

One seat that sees every screen.

Run /missioncache:lead-start in any Claude Code session. It becomes the lead: the one place that knows what every other session is doing.

  • 01
    A brief across all your projectsWhat is urgent, what is waiting on someone, which sessions are live, and today's calendar if you connect one.
  • 02
    Every session reports inWhen a session changes its project, it sends the lead one line. The lead holds them for its next brief, so it never interrupts you.
  • 03
    You set the pace, and it stopsThe lead asks how often to check and for how long. It never loops on its own, and it stops after 7 hours unless you pick another window.

Install

Three minutes to your first project.

A wizard asks which parts you want and which AI tools to register. Needs Python 3.11+. The uvx command comes with uv.

Full install

plugin · dashboard · statusline · auto · lead
$uvx missioncache-install

Use --all --yes for a hands-off run. pipx run missioncache-install works too.

Plugin only

slash commands · MCP tools · hooks · lead
$/plugin marketplace add missioncache/missioncache

Inside Claude Code, then /plugin install missioncache@missioncache. No dashboard or statusline.

FAQ

The questions people actually ask.

How is this different from CLAUDE.md or built-in memory?

CLAUDE.md is a static rules file you maintain by hand. MissionCache keeps living project state (the plan, your decisions, the gotchas, progress) that updates as you work and reloads with one command. It complements CLAUDE.md, it does not replace it.

What does the lead session actually do?

It runs a brief across every project, then receives a one-line notice whenever another session changes a project. If you want, it refreshes the brief on a schedule you pick, and it stops at the end of the window you set (7 hours by default). It never starts that loop on its own. It needs Claude Code, because it relies on cross-session messaging.

Can I run two sessions on the same project?

Yes. Every write waits on the project's lock and lands in one piece, so two sessions never corrupt the context file or overwrite each other. When one session changes the project, the others are told. Each session keeps its own reasoning. The project files are what they share.

Where does my data live?

On your machine. Project files are plain markdown under ~/.missioncache/, and the dashboard listens on 127.0.0.1 only. There is no account and no MissionCache server.

Which tools does it work with?

Claude Code gets everything: the lead, hooks, dashboard, statusline and autonomous runs. Codex, OpenCode and VSCode Copilot Chat get the project files, the slash commands and every MCP tool. Start a project in one and pick it up in another.

Isn't this just cross-agent memory like claude-mem?

claude-mem recalls memories into whatever agent you are in. MissionCache moves the whole project: the plan you approved, the tasks with their progress, the decisions and gotchas, as files any MCP agent reads and writes. If you want long-lived memory across projects, claude-mem is genuinely good at that.

Doesn't compaction already keep the context?

It keeps a summary, and every summary drops details: an edge case, a constraint, a “don’t do X”. Anthropic calls this goal drift. MissionCache keeps the plan, the decisions and the next step in files, so a session reloads them in full instead of trusting the summary.

Does it work on Windows?

Yes, on native Windows with no WSL. The hooks run, including the compaction snapshot, and the dashboard starts at logon. It needs Claude Code 2.1.139 or newer. A Windows CI job tests all of this on every push.

Is it free, and can I remove it?

Yes and yes. It is open source under the MIT license. To remove it, uninstall the packages and delete ~/.missioncache. Your projects are plain markdown, so anything you want to keep, you keep.
